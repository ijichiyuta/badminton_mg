# ADR-0006 同率処理は「指標」と「母集団スコープ」に分解する

日付: 2026-09-13 / 状態: 採択（ADR なし版の記述を置き換える）

## 背景
旧版の `docs/05-ranking-engine.md` は、判定基準のリストに `headToHead`（直接対決）を
他の指標と並べて置いていた。その上で別途 `tiebreakScope: AMONG_TIED`（当該者間で再計算）という
設定も持っていた。

この2つは同じことを表現している。「当該者間のみの成績で勝数を比較する」ことが、
2者のときは直接対決そのものであり、3者以上のときは当該者間の勝敗表である。
概念が二重化しており、設定の組み合わせによって説明できない挙動が出る。

さらに旧版の擬似コードは、同率グループを分割したあと判定基準の index を 1 に戻していた。
これは `criteria[0]`（勝数）を**当該者間で再評価しない**ことを意味する。
しかし日本の大会要項の標準的な文面は「当該者間の勝敗による」から始まる。
3者同率が当該者間の勝数で解けるケースを取りこぼす、実装上のバグである。

## 決定
判定を2つの独立した軸に分解する。

| 軸 | 内容 |
|---|---|
| **指標**（`criteria`） | 何を比べるか。`wins` / `points` / `matchRatio` / `gameRatio` / `pointRatio` / `matchDiff` / `gameDiff` / `pointDiff` |
| **母集団スコープ**（`tiebreakScope`） | 誰との対戦成績で比べるか。`AMONG_TIED` / `ALL_MATCHES` / `AMONG_TIED_IF_TWO` |

`headToHead` は**指標のリストから削除する**。
2者同率における直接対決は、`AMONG_TIED` スコープで `criteria[0]` を評価した結果として自動的に得られる。

同率処理では、スコープを切り替えたうえで**必ず `criteria[0]` から再評価する**。

## 理由
- 2つの軸に分けることで、要項の文面と1対1で対応づけられる。
  「当該者間の勝敗 → ゲーム率 → ポイント率」は `scope=AMONG_TIED, criteria=[wins, gameRatio, pointRatio]` の1通りにしか書けない
- `headToHead` を特別扱いしないため、「3者以上では適用不可」という分岐が消える
- 分割のたびに集合が真に小さくなるため、再帰の停止が構造的に保証される。
  旧版が必要としていた無限ループ対策が不要になる

## 結果
- 旧版の `RankingRuleSet.criteria` に `headToHead` を含む保存データは、
  マイグレーションで `headToHead` を除去し `tiebreakScope` へ変換する必要がある（`schemaVersion` 1 → 2）
- 「3者以上のときは直接対決を使わない」という要項には `AMONG_TIED_IF_TWO` で対応する
- 設定項目が1つ増えるが、UI には出さない。要項パターンのプリセット選択で設定する（`docs/13-operator-load.md`）
