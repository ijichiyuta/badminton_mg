# 進行形式の仕様

## 1. トーナメント（SINGLE_ELIMINATION）

### ブラケットサイズ
参加数以上で最小の2のべき乗。4〜128 に対応する。
余った枠は BYE として配置する。

### シード位置の決定（標準ブラケット順）

シード位置は表で持たず、**再帰的に生成する**。4〜128 のすべてで同じ規則が使える。

```
S(2) = [1, 2]

S(2n) を S(n) から作る：
    S(n) の i 番目の要素 x について
        i が奇数 → (x, 2n + 1 - x) の順で並べる
        i が偶数 → (2n + 1 - x, x) の順で並べる
```

生成される配列 `S(N)` は**自己逆写像**であり、1つの配列で
「シード s の位置」と「位置 p に入るシード」の両方を表す（`S[s]` が位置、`S[p]` がシード）。

```
S(4)  = [1, 4, 3, 2]
S(8)  = [1, 8, 5, 4, 3, 6, 7, 2]
S(16) = [1, 16, 9, 8, 5, 12, 13, 4, 3, 14, 11, 6, 7, 10, 15, 2]
S(32) = [1, 32, 17, 16, 9, 24, 25, 8, 5, 28, 21, 12, 13, 20, 29, 4,
         3, 30, 19, 14, 11, 22, 27, 6, 7, 26, 23, 10, 15, 18, 31, 2]
```

| ブラケット | 第1 | 第2 | 第3・4 | 第5〜8 |
|---|---|---|---|---|
| 16 | 1 | 16 | **9, 8** | **5, 12, 13, 4** |
| 32 | 1 | 32 | **17, 16** | **9, 24, 25, 8** |

#### 検証済みの性質（実装のアサーションにする）

`S(N)` が正しく生成できていれば、次がすべて成り立つ。テストで確認すること。

| 性質 | 16ドローでの確認 |
|---|---|
| 自己逆写像である（`S[S[i]] == i`） | 4 / 8 / 16 / 32 で成立 |
| 1回戦の対戦カードは、シード番号の和が `N+1` になる | (1,16)(9,8)(5,12)(13,4)(3,14)(11,6)(7,10)(15,2) |
| 各クォーターに入るシード番号の和が等しい | 第1〜第4クォーターすべて 34 |
| 第1シードと同じクォーターに入るのは第8シード | Q1 = {1, 8, 9, 16} |
| 第4シードと同じクォーターに入るのは第5シード | Q2 = {4, 5, 12, 13} |

**「各クォーターの和が等しい」が、旧版の表で崩れていた性質である。**

> **旧版の表（16枠で 第3・4 = 5,12 / 第5〜8 = 3,7,10,14）は誤り。**
> 各クォーターに1名ずつ入る点は満たしていたが、**強弱の釣り合いが取れていない。**
> 正しい配置では、第5シードが第4シードと同じクォーターに、第8シードが第1シードと同じクォーターに入る。
> 旧版では第5シードが第1シードと同じクォーターに入り、上位ブロックに強者が偏る。
>
> ただし日本の大会では表の描き方の慣習が団体ごとに異なる。
> **前年の組み合わせ表（Q A-7）と必ず突き合わせること。** 去年と形が違うと現場で必ず指摘される。

第3シード以降を抽選で決めるか固定するかは運用による。→ Q C-2

### BYE の配置

**BYE は「シードが入る枠」ではなく「シードの初戦の相手の枠」に置く。**

```
必要な BYE 数 = ブラケットサイズ − 参加数
配置順        = 第1シードの相手 → 第2シードの相手 → 第3シードの相手 → …
```

シード位置 `p` の初戦の相手枠は、`p` が奇数なら `p+1`、偶数なら `p-1`。

**例：16枠・参加13名（BYE 3つ）**

| 順 | シード | シード位置 | **BYE を置く位置** |
|---|---|---|---|
| 1 | 第1シード | 1 | **2** |
| 2 | 第2シード | 16 | **15** |
| 3 | 第3シード | 9 | **10** |

（検証済み：16枠13名 → BYE は 2, 15, 10）

> **旧版の記述（「位置は 1番、9番、5番」）は誤り。** これはシード本人の位置である。
> そのまま実装すると第1シードがブラケットから消える。

BYE 数がシード数を超える場合は、実際にシードが置かれているかに関わらず
`S(N)` の並び順を仮想的に延長し、その相手枠へ順に配置する（第4シード位置の相手 = 7番、以下同様）。

BYE の Match は `status = COMPLETED` / `resultType = BYE` とし、勝者を自動確定する。
**ゲーム率・ポイント率の分母に含めない**（`docs/05-ranking-engine.md`）。

### 順位決定戦
- 3位決定戦：あり／なし（設定）
- 3位決定戦なしの場合、準決勝敗者は**両者3位**とし、4位は欠番とする
- 5〜8位決定戦：あり／なし（設定）

賞状・表彰の枚数に直結するため、設定値は結果一覧の印刷に反映すること。

## 2. リーグ戦（ROUND_ROBIN）

### ブロック分割
- ブロック数を指定する方式と、1ブロックあたりの人数を指定する方式の両方に対応
- 端数が出る場合、上位のブロックから多く配分する（3名・3名・2名）
- 分割時の制約：同一所属を同じブロックに入れない（可能な範囲で）

**人数の異なるブロックが混在する場合、勝利数の単純比較はできない。**
ブロックをまたいだ成績比較（ワイルドカードの選抜など）では、
`wins` ではなく率系の指標を使うよう警告を出す。

### 対戦順序
1ブロック内の対戦順は、連続出場を避ける標準的な巡回スケジュールで生成する。

```
3名：(1-2) (1-3) (2-3)
4名：(1-4)(2-3) (1-3)(2-4) (1-2)(3-4)
5名：総当たり10試合を、各選手が連続しないよう配置
6名：15試合
```

### 順位決定
→ `docs/05-ranking-engine.md`

## 3. 予選リーグ → 決勝トーナメント

**独立した形式ではない。** `ROUND_ROBIN` ステージ + `SINGLE_ELIMINATION` ステージ + `AdvancementRule`。

### 進出者の配置
最も間違えやすい部分。**同一ブロック出身者が1回戦で当たってはならない。**

4ブロックから各上位2名（計8名）が進出する場合の標準的な配置：

```
1回戦
  A組1位 vs B組2位
  C組1位 vs D組2位
  B組1位 vs A組2位
  D組1位 vs C組2位
```

各ブロック1位が別の山に分かれ、同組の1位と2位は決勝まで当たらない。

ブロック数が2のべき乗でない場合（3ブロック、5ブロックなど）は、
進出者数がブラケットサイズに満たないため BYE を配置する。
このとき BYE は**各ブロック1位に優先して割り当てる**（上記のシード規則を準用）。

### 進出の確定タイミング（旧版から変更）

旧版は「1ブロックでも未完了なら決勝トーナメントは開始できない」としていた。
**これは現場の実態と合わず、UX原則5（エラーで止めない）にも反するため撤回する。**

新しい仕様：

| 状態 | 動作 |
|---|---|
| 全ブロック完了 | 進出者を自動で流し込み、決勝トーナメントを確定する |
| 一部ブロックのみ完了 | **確定したブロックの進出者だけを先に配置できる。** 未確定枠は「A組1位（未確定）」と表示する |
| 未確定枠を含む試合の開始 | 警告を出すが、ブロックはしない |

1人運用では、全ブロックの終了を待ってから決勝を組むと進行が止まる。
**先に終わったブロックから決勝の一部を始めるのは、ローカル大会では通常運転である。**

## 4. 予選リーグ → 決勝リーグ

`ROUND_ROBIN` + `ROUND_ROBIN`。
決勝リーグでは、予選で対戦済みの組み合わせの成績を持ち越すか否かの設定が必要。

- 持ち越さない（決勝リーグ内で再び対戦する）
- 持ち越す（予選の対戦結果をそのまま使い、その組み合わせは再戦しない）

持ち越す設定では、決勝リーグの各エントリーの**実施試合数が異なり得る**。
勝利数ではなく率系の指標で順位を決めないと不公平になるため、検証で警告する。

→ Q E-1 で要項を確認する

## 5. 敗者戦・順位別リーグ（CONSOLATION）

1回戦敗者だけを集めた別トーナメント、あるいは予選ブロック下位者による順位別リーグ。
ローカル大会では「1試合で終わるのは可哀想」という理由でよく行われる。

`SINGLE_ELIMINATION` または `ROUND_ROBIN` の Stage として表現し、
`AdvancementRule` の取得条件を「敗者」「各ブロック3位以下」とする。

**BYE で勝ち上がった選手（1試合も行っていない）が敗者戦に落ちることはない**が、
BYE の相手が欠場だった場合など、1試合も消化しないまま敗退扱いになる経路がある。
敗者戦の母集団を作るときは `resultType = BYE` を除外すること。

## 6. 順位決定戦・入れ替え戦（PLAYOFF）

特定の順位を決めるための単発の試合、または部の入れ替えを決める試合。
2〜4エントリー程度の小規模な Stage として表現する。

`RankingRuleSet.unresolvedAction = PLAYOFF` のとき、このステージが自動生成される。

## 7. 団体戦

団体戦は「進行形式」ではなく「対戦の中身」である。
上記1〜6のいずれの形式とも組み合わさる。

### 編成パターン

| パターン | 構成 | よく使われる場面 |
|---|---|---|
| **3複** | D-D-D | **新日本スポーツ連盟の全国団体戦。第1=女子D／第2=男子D／第3=混合D** |
| 3複2単 | D-D-S-D-S など | 一般・実業団 |
| 2複3単 | 順序は要項による | 高校男子 |
| 2複1単 | | 中学 |
| 5複 | | ダブルス主体の市民大会 |
| 4複1単 | | |
| 任意 | 単複の数と順序を自由定義 | |

### 各試合の種別制約

**Tie 内の各スロットに、出場できる種別の制約があることが多い。**

第1号提供先の全国団体戦（3複）の例：

| スロット | 種別 | 制約 |
|---|---|---|
| 第1ダブルス | 女子ダブルス | 女子2名 |
| 第2ダブルス | 男子ダブルス | 男子2名 |
| 第3ダブルス | 混合ダブルス | 男子1名・女子1名 |

チーム構成の下限（「1チーム8名上限、男子2名以上・女子2名以上」）も同じ枠組みで検証する。
違反は警告のみ。ブロックしない。

### 勝敗判定
過半数の Match を先に取ったチームが勝ち。

### 打ち切り（Stage が持つ）

**打ち切り設定は Tie ではなく Stage の設定である。**
第1号提供先の要項では、同じ大会・同じ種目の中でステージによって切り替わる。

> 予選４チームリーグは、**３ダブルスすべて実施**。
> その後各予選リーグ１位による決勝トーナメント戦を**(２勝先取)**を行う。

| ステージ | 設定 | 意味 |
|---|---|---|
| 予選リーグ | `truncate: false` | 全 Match を消化する |
| 決勝トーナメント | `truncate: true` | 過半数確定で残りを `NOT_PLAYED` にする |

打ち切られた Match はゲーム率・ポイント率の分母から除外する。

**リーグ戦で順位決定にゲーム率を使う大会では、打ち切ると不公平が生じるため全試合消化とすることが多い。**
実際、第1号提供先も**予選リーグだけ全試合消化**にしている。
`truncate = true` かつ順位決定基準に `gameRatio` / `pointRatio` / `matchRatio` が含まれる場合は警告を出す。

### オーダー

各 Tie の直前に、両チームが誰をどの Match に出すか提出する。
事前一括提出の大会もある。→ Q D-5

**オーダーは「未提出」という状態を持つ。** 提出されていない Tie はコートに割り当てられない。
1人運用では、オーダー未提出のチームを探して回るのが最大の時間損失になるため、
ホーム画面に「オーダー未提出のチーム」を常時表示する（`docs/13-operator-load.md`）。

同一選手が1つの Tie 内で複数の Match に出られるかは要項による。→ Q D-6
