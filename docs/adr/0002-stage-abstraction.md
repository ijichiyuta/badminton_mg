# ADR-0002 進行形式をステージの組み合わせで表現する

日付: 2026-09-13 / 状態: 採択

## 背景
対応が必要な形式は、トーナメント、リーグ（ブロック戦）、予選リーグ→決勝トーナメント、団体戦。
さらに敗者戦、順位決定戦、予選リーグ→決勝リーグの要望も出うる。

これらを形式ごとに実装すると、組み合わせ爆発を起こす。

## 決定
形式を4つの**ステージ種別**に還元し、ステージを**進出ルールで連結**することで
すべての進行パターンを表現する。

- `SINGLE_ELIMINATION`
- `ROUND_ROBIN`
- `CONSOLATION`
- `PLAYOFF`

「予選リーグ→決勝トーナメント」は形式名ではなく、
`ROUND_ROBIN` + `SINGLE_ELIMINATION` + `AdvancementRule` である。

団体戦は進行形式ではなく「対戦の中身」であり、上記いずれの形式とも直交する。
`Tie` が複数の `Match` を内包する入れ子構造で表現する。

## 理由
- 形式ごとの分岐を増やす実装は、3つ目の形式で破綻する
- ローカル大会の形式は要項ごとに少しずつ違う。組み合わせで表現できないと毎回改修になる
- 進出ルールを独立させることで、交差配置や敗者復活を共通化できる

## 結果
- 初期の実装コストは形式ごとに作るより高い
- 一方で、新しい形式の要望にはステージの組み合わせで対応でき、コードを触らずに済む場合がある
- **この抽象化を崩す実装は却下する**
