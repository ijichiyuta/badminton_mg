# ADR-0005 採点方式を設定値とし、既定を15点制にする

日付: 2026-09-13 / 状態: 採択

## 背景
国内大会は 3ゲーム×15点制へ移行する予定である。一方で移行時期は団体ごとにばらつき、
当面は21点制の大会が併存する。級別・年齢別で方式が混在する大会もある。

## 決定
1. 採点方式は `ScoringRuleSet` として設定値で持つ。**既定値は 15点3ゲーム制**
2. 21点3ゲーム制を含む複数のプリセットを用意し、ワンタップで切り替えられる
3. 点数に関する定数をドメイン層のコードに直接書かない
4. 上書きの粒度は **Tournament → Event → Stage の3段階**。Group / Match 単位は持たない
5. `maxPoints` は「その点を取った側が勝つ点数」と定義する（21点制=30、15点制=21）

## 理由
- 移行期に方式が変わるたびに改修が必要な設計は、年1回の大会で致命的になる
- 既定を15点にするのは、今後の新規大会が15点制で開催される見込みが高いため。
  ただし**既定値であって前提ではない**。21点制の大会がプリセット選択1回で使える状態を維持する
- Stage 単位の上書きを許すのは、**「予選は1ゲーム、決勝は3ゲーム」がローカル大会で最も多い運用**だから。
  これは同一種目内の話であり、種目を分けても表現できない
- Group / Match 単位を持たないのは、**1ステージ内では単一の方式である**ことを保証するため。
  順位決定の集計が常に同じ母数の上で行われる（不変条件7）
- 設定負担は粒度を制限して減らすのではなく、**ステージ構成プリセット**で吸収する。
  運営者が選ぶのは「予選1ゲーム → 決勝3ゲーム」という1項目である

## 結果
- 同一ステージ内で採点方式が混在し得る。ポイント率・ゲーム率による順位決定と組み合わせると
  不公平が生じるため、混在検知の警告を実装する必要がある（`docs/06-scoring.md`）
- 前年大会の複製で採点方式も複製されるため、複製時に明示的な確認を挟む必要がある
- 過去大会とのポイント関連指標の比較ができなくなる。CSV 出力に `pointsPerGame` を必ず含める
- `carryOverResults`（予選の成績を決勝リーグへ持ち越す）と、
  ステージ間で異なる採点方式の組み合わせは破綻する。検証で強い警告を出す

## 改訂履歴

### 2026-09-13 決定4を撤回・変更

初版では「上書きは Tournament → Event の2段階のみ。種目より細かく方式が変わる大会は
種目を分けて登録する運用で吸収する」としていた。

**これは頻出パターンを潰していた。**
「予選リーグは21点1ゲーム、決勝トーナメントは21点3ゲーム」は同一種目内の話であり、
種目を分けても表現できない。しかもローカル大会では最も多い運用である。

設定項目を減らす意図で置いた制約だったが、**制約の置き場所を間違えていた。**
制限すべきは上書きの粒度ではなく、運営者に見せる設定の数である。
Stage 単位の上書きを許したうえで、ステージ構成プリセットで設定負担を吸収する形に改めた。
