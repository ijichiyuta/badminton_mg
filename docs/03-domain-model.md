# ドメインモデル

## 構造

```
Tournament（大会）
 ├─ Court[]                      コート
 ├─ RankingRuleSet               順位決定ルール（大会共通の既定値）
 ├─ ScoringRuleSet               採点方式（大会共通の既定値）
 └─ Event[]（種目）
     ├─ RankingRuleSet?          種目ごとの上書き
     ├─ ScoringRuleSet?          種目ごとの上書き
     ├─ Entry[]（エントリー）
     └─ Stage[]（ステージ・順序付き）
         ├─ ScoringRuleSet?      ステージごとの上書き（予選1ゲーム／決勝3ゲーム）
         ├─ AdvancementRule?     前ステージからの進出定義
         ├─ Group[]（組）  ← ScoringRuleSet? を持てる
         └─ Match[]（試合）
             ├─ Game[]
             └─ Tie?             団体戦のときのみ
```

### ルールセットの上書き粒度

| ルールセット | 上書きできる階層 |
|---|---|
| `ScoringRuleSet`（採点方式） | Tournament → Event → Stage → **Group** |
| `RankingRuleSet`（順位決定） | Tournament → Event |

採点方式が Stage まで下りるのは、**「予選は1ゲーム、決勝は3ゲーム」がローカル大会で最も多い運用**
だからである。同一種目内の話であり、種目を分けても表現できない（`docs/adr/0005` 改訂履歴）。

**Match 単位の上書きは持たない。** 1ブロック内では必ず単一の採点方式が適用される（不変条件7）。
リーグ戦の順位はブロック内でのみ比較するため、ブロック間で方式が違っても不公平は生じない。

Group まで下ろすのは、**同じ種目の中でブロックのチーム数が違い、
試合数が多いブロックだけ延長をなくす**運用が実在するため（`docs/17-first-customer.md`）。

設定負担は粒度の制限ではなく、**ステージ構成プリセット**で吸収する（`docs/06-scoring.md`）。

## 主要エンティティ

### Tournament
大会そのもの。名称、開催日、会場、コート構成、既定のルールセットを持つ。
**前年の大会を丸ごと複製できること**が要件（`docs/07` F-1-5）。

複製時、採点方式は**明示的な確認を挟む**。15点制への移行期に、
前年の21点制設定を気づかず引き継ぐ事故を防ぐ（`docs/06-scoring.md`）。

### Event（種目）
男子シングルス、女子ダブルスA級、団体戦など。
ルールセットは大会の既定値を継承し、必要なら種目単位で上書きする。

### Entry（エントリー）
種目への出場単位。3つの形態を取る。

| 形態 | 内容 |
|---|---|
| `INDIVIDUAL` | 選手1名 |
| `PAIR` | 選手2名 |
| `TEAM` | チーム1つ。所属選手を複数持つ |

Entry は選手（Player）を参照する。Player は **大会内でのみ一意**とする。
大会をまたいだ同一人物の名寄せは v1 では行わない。

#### Entry の状態

| 状態 | 意味 |
|---|---|
| `ACTIVE` | 出場中 |
| `WITHDRAWN` | 欠場。組み合わせ確定前なら除外、確定後なら不戦敗として扱う |
| `SUBSTITUTED` | 構成選手が入れ替わった（ペアの片方交代など）。エントリー自体は存続する |

**ペアの片方だけが来ない、という事態はローカル大会で常に起きる。**
`playerIds` を直接編集できるようにし、変更内容を `operationLog` に残す。
Entry の id は変更しない（Match の参照が壊れるため）。→ Q C-8

### Stage（ステージ）
種目内の進行段階。1種目に1つ以上、順序を持って並ぶ。

| 種別 | 内容 |
|---|---|
| `SINGLE_ELIMINATION` | 勝ち抜き戦。3位決定戦・5〜8位決定戦のオプションを持つ |
| `ROUND_ROBIN` | 総当たり。複数の Group に分割される |
| `CONSOLATION` | 敗者戦、順位別リーグ |
| `PLAYOFF` | 順位決定戦、入れ替え戦 |

**この抽象化が設計の要**。詳細は `docs/adr/0002-stage-abstraction.md`。

Stage は `scoringRule` を持てる。`null` なら Event → Tournament の順に継承する。
ステージが3段階以上ある場合、ステージ構成プリセットは
**最後に指定された方式を以降のステージへ引き継ぐ**。

### AdvancementRule（進出ルール）
ステージ間を接続する定義。

```
- 取得元ステージ
- 各グループから上位何名／何チームを取るか
- 全グループ横断での成績上位を敗者復活させるか（ワイルドカード枠数）
- 次ステージへの配置方針
    - 同一グループ出身者を早期に当てない（交差配置）
    - 同一所属をできるだけ分散させる
    - 手動での入れ替えを許可する
- 部分進出を許可するか（既定：許可）
```

**部分進出**：取得元ステージの一部のグループだけが完了している状態でも、
確定した分を次ステージへ流し込める。未確定の枠は「A組1位（未確定）」として保持する。
`docs/04-formats.md` 3節を参照。

### Match（試合）

1つの対戦。**状態を2つの直交した軸で持つ。**

#### 軸1：進行状態（`status`）

いま試合がどこまで進んでいるか。時間とともに前へ進む。

| 値 | 意味 |
|---|---|
| `PENDING` | 対戦相手が未確定 |
| `READY` | 対戦相手確定。コート未割当 |
| `SCHEDULED` | コートと時間が割り当てられた |
| `IN_PROGRESS` | 試合中 |
| `COMPLETED` | 結果確定 |

#### 軸2：結果種別（`resultType`）

どういう決まり方をしたか。`status = COMPLETED` のときに意味を持つ。

| 値 | 意味 | 勝者 | ゲーム率の分母 |
|---|---|---|---|
| `NORMAL` | 通常の試合 | あり | 含む |
| `BYE` | 不戦勝。試合は行われない | あり | **含まない** |
| `WALKOVER` | 没収試合 | **あり** | 設定による |
| `RETIRED` | 試合中の棄権 | あり | 設定による |
| `WITHDRAWN` | 試合前の欠場 | あり | 設定による |
| `DISQUALIFIED` | 失格 | あり | 設定による |
| `NOT_PLAYED` | 団体戦の打ち切りにより実施されなかった | **なし** | **含まない** |

> **旧版はこの2つを1つの enum に混ぜていた。** 進行状態と結果種別は直交する概念であり
> （「没収試合が SCHEDULED」はあり得る）、混ぜると状態機械が破綻する。

`NOT_PLAYED` は**唯一、勝者を持たない `COMPLETED`** である。

### Tie（団体戦の対戦）
チーム対チームの1対戦。内部に複数の `Match` を持つ。

```
- 編成パターン（3複2単・3複 など）
- 試合順序と、各試合の種別制約
- 各チームのオーダー（どの Match に誰を出すか）
- オーダーの提出状態（未提出 / 片側のみ / 両者提出済み）
- 勝敗判定（先に過半数の Match を取った方が勝ち）
```

#### 各試合の種別制約（`slotConstraint`）

団体戦では、Tie 内の各試合に**出場できる性別・種別の制約がある**ことが多い。

第1号提供先の全国団体戦の例（3ダブルス制）：

| スロット | 種別 | 制約 |
|---|---|---|
| 第1ダブルス | 女子ダブルス | 女子2名 |
| 第2ダブルス | 男子ダブルス | 男子2名 |
| 第3ダブルス | 混合ダブルス | 男子1名・女子1名 |

**オーダー入力時にこの制約を検証する。** 違反は警告を出すが、ブロックはしない（原則5）。
チーム構成の下限（「男子2名以上・女子2名以上」など）も同じ枠組みで検証する。

#### 打ち切りは Stage が持つ

**打ち切り設定は Tie ではなく Stage に持たせる。**
第1号提供先では、**予選リーグは3ダブルスすべて実施、決勝は2勝先取**であり、
同じ大会・同じ種目の中でステージによって切り替わる。

Tie 個別の上書きは持たない。

Match が Tie を内包するのではなく、**Tie が Match を内包する**。階層を逆にしないこと。

**オーダー未提出の Tie はコートに割り当てられない。** 提出状態を明示的に持つ。

## 不変条件

実装時にアサーションとして持たせる。**旧版から2件を修正した。**

1. 1つの Entry が同一時刻に2つのコートに割り当てられない
2. `status = COMPLETED` かつ `resultType ≠ NOT_PLAYED` の Match には、必ず勝者が存在する
   （旧版は `WALKOVER` を除外していたが、没収試合には勝者が存在する。誤り）
3. **進出者数 ≤ 次ステージのブラケットサイズ。** 差は BYE で埋まる
   （旧版は「進出者数 = 次ステージのエントリー数」としていたが、
   3ブロック・5ブロックやワイルドカード枠では一致しない。誤り）
4. Tie の Match 数は、編成パターンで定義された数と一致する
5. 結果を取り消した場合、それに依存する後続の Match は `PENDING` に戻る
6. `status = SCHEDULED` 以降の Tie は、オーダーが両チーム提出済みである
7. **1つの Group 内の全 Match は、同一の `ScoringRuleSet` を参照する。**
   ステージ間・ブロック間の方式の違いは正規の運用だが、ブロック内の混在は集計を壊す。
   違反する場合はエラー相当の強い警告を出す（それでもブロックはしない）
8. `resultType = BYE` の Match は `games` を持たない
