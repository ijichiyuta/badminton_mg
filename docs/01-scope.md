# スコープ

## 目的

小規模ローカル大会において、紙のスコアシート・ホワイトボード・電卓による集計を置き換える。

## 背景

バドミントンの大会運営ソフトとしては「めざせ！全自動」（Windows アプリ）が事実上の標準であり、
市民大会から全日本社会人選手権まで広く使われている。一方で、それを導入していない小規模なローカル大会では、
いまだに紙での集計が行われている。本システムはその層を対象とする。

既存の無料 Web ツールは、トーナメント表の作成と結果表示には対応しているが、
**リーグ戦の順位決定ロジック、団体戦、予選リーグから決勝トーナメントへの進出処理**には対応していない。
そこが本システムの存在理由である。

## 三つの制約

| # | 制約 | 由来 |
|---|---|---|
| C1 | トーナメント／リーグ／予選リーグ→決勝トーナメント／団体戦のすべてに対応する | ローカル大会の形式は一定しないため |
| C2 | 通信を機能の前提条件にしない。アップロード時のみ通信を使う | 体育館の電波状況が保証できないため |
| C3 | 運営者が1人でも大会を完走できる | 小規模大会の人員実態 |

C2 と C3 の組み合わせが最も厳しい。オフラインかつ1人ということは、
**端末が1台壊れた時点で大会が止まる**。データ保全が最優先の非機能要件になる。

### C3 は「操作を速くする」ことではない

1人運用で最も時間を奪うのは入力ではなく、**中断**である。
「次いつ？何番コート？」「オーダーまだ？」「なぜこの順位？」に答える時間が、
スコアシートを転記する時間より長い。

負担を5つ（設定・準備・入力・判断・中断）に分解し、
機能追加はそのいずれかを減らすものに限る。→ `docs/13-operator-load.md`

## v1 でやること

- 大会・種目・参加者の登録
- 4形式すべての組み合わせ作成（自動生成＋手動調整）
- 試合結果の入力と自動集計
- 順位決定ルールエンジン
- トーナメント表／リーグ表の表示と印刷
- JSON によるエクスポート・インポート
- 完全なオフライン動作
- 15点3ゲーム制を既定とし、21点制をプリセットで切り替えられること

## v1 でやらないこと（非目標）

明示的に対象外とする。実装中に迷ったらここへ戻る。

- 参加費の決済・集金
- 日本バドミントン協会の会員登録システムとの連携
- ライブストリーミング、動画、写真
- 複数端末でのリアルタイム同期
- ネイティブアプリ化
- 賞状の自動印刷
- 大会をまたいだ選手戦績の蓄積
- 他競技への対応

## 成功の定義

v1 の成功は機能数ではなく、次の1点で測る。

**対象の大会を1回、システムだけで完走できること。**
（初回は紙と並行運用するため、「紙より速く、紙と同じ結果が出た」であれば成功とみなす）

補助的な検証指標を3つ置く。いずれも1人運用が成立したかを測るもの。

| 指標 | 目標 |
|---|---|
| 運営者が手を止めて判断を求められた回数 | 1大会 5回以内 |
| 1試合の結果入力にかかった時間 | 15秒以内 |
| 「次いつ？」「何番コート？」と聞かれた回数 | 紙運用時より減っていること |

3つ目が最も重要で、最も測りにくい。**当日の記録を取ることを事前に決めておく。**
