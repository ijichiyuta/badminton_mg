# 運営負担の削減設計（1人運用）

制約 C3「運営者が1人でも大会を完走できる」を、機能要件に落とすための文書。
**新しい機能を入れるかどうかは、この文書の観点で判断する。**

## 前提：負担は「入力」ではない

1人運用で最も時間を奪うのは、結果入力そのものではない。**中断である。**

体育館で1人の運営者に起きていることを時間順に並べる。

| 時間帯 | 起きること | 負担の種類 |
|---|---|---|
| 開場〜受付 | 受付、欠場の受理、組み合わせの修正 | **ピーク。ここで崩れると1日崩れる** |
| 進行中 | スコアシートの回収と転記 | 入力 |
| 進行中 | 「次いつ？」「何番コート？」の質問対応 | **中断** |
| 進行中 | 「オーダーまだ出てない」の督促 | 中断 |
| 進行中 | コートが空いたのに次を呼べていない | 判断 |
| 予選終了時 | 順位の確定と決勝の組み直し | **判断のピーク** |
| 順位が揉めたとき | 選手への説明 | 中断＋信用 |
| 表彰前 | 結果の集計・賞状・掲示 | 締切のある作業 |

入力は全体の一部でしかない。**中断を減らすことが、入力を速くすることより効く。**

## 負担を5つに分解する

| # | 負担 | 削減の方針 |
|---|---|---|
| O-1 | **設定の負担** | 運営者に設定させない。選ばせる |
| O-2 | **準備の負担** | 前年から複製する。手入力を発生させない |
| O-3 | **入力の負担** | 転記を最短経路にする。連続入力から出させない |
| O-4 | **判断の負担** | 次の行動をシステムが提示する。揉め事は根拠で終わらせる |
| O-5 | **中断の負担** | 聞かれる前に答えを出しておく。人に委譲する |

---

## O-1 設定の負担を減らす

順位決定ルールエンジンは強力になるほど設定項目が増える。これは1人運用と正面から衝突する。

### O-1-1 要項プリセットから選ばせる

`RankingRuleSet` の項目を運営者に1つずつ設定させない。
**要項の定型文に対応したプリセットを提示し、1つ選ばせる。**

| プリセット | 対応する要項の文面 | 設定内容 |
|---|---|---|
| **標準（当該者間）** | 「勝数による。同数の場合は当該者間の成績による」 | `scope=AMONG_TIED, criteria=[wins, gameRatio, pointRatio]` |
| 直接対決（2者のみ） | 「2者の場合は直接対決による。3者以上はゲーム率による」 | `scope=AMONG_TIED_IF_TWO` |
| 全試合成績 | 「ゲーム率の高い者を上位とする」 | `scope=ALL_MATCHES` |
| 得失差方式 | 「得失ゲーム差による」 | `criteria=[wins, gameDiff, pointDiff]` |
| 勝点方式 | 「勝点（勝1・負0・棄権-1）による」 | `criteria=[points, matchRatio, gameRatio]` |

個別項目は「詳細設定」に隠す。**既定のプリセットを選ぶだけで大会が回ること。**

### O-1-2 結果が変わらない設定は聞かない

棄権者の扱いなど、要項に規定がなく運営者が判断を迫られる設定がある。
**両方の設定で順位が同じなら、選択を求めない。** 異なる場合にのみ提示する。

```
「棄権者との対戦成績を削除しても、A組の順位は変わりません」  → 選択不要。そのまま進む
「削除すると2位と3位が入れ替わります」                    → 両方を並べて提示
```

### O-1-3 採点方式はプリセット1タップ

**2階層のプリセットを用意する。** 点数・ゲーム数・上限を個別に設定させない。

| 階層 | 選ぶもの | 例 |
|---|---|---|
| ステージ構成 | 大会全体でどう使い分けるか | 「予選1ゲーム → 決勝3ゲーム（15点）」 |
| ゲーム形式 | 個別のステージに何を当てるか | 「15点3ゲーム制」「10分1本勝負」 |

**通常はステージ構成プリセットを1つ選べば終わる。**
ゲーム形式を個別に当てるのは、当てはまるステージ構成プリセットがないときだけ。
デュース上限・インターバル・2点差ルールは詳細設定に隠す。

> 「予選は1ゲーム、決勝は3ゲーム」はローカル大会で最も多い運用である。
> これを表現するために運営者へ2回設定させると、O-1 の削減が台無しになる。
> **頻出の組み合わせ自体をプリセットにする**のが正解。

### O-1-4 形式を人数から提案する

参加者を登録した時点で、人数に応じた形式を提案する。

```
「12名です。次のどれにしますか」
  ・4ブロック3名の予選リーグ → 各1位が決勝トーナメント（推奨）
  ・16ドローのトーナメント（BYE 4つ）
  ・3ブロック4名の予選リーグ → 上位2名が決勝トーナメント
```

**白紙から組ませない。** 提案を直す方が、ゼロから作るより速い。

## O-2 準備の負担を減らす

### O-2-1 前年大会の複製を最上位の導線に置く

ホーム画面の「新しい大会」より先に「**前年の大会から作る**」を置く。
複製されるもの：種目構成、ルールセット、コート設定、印刷設定。
複製されないもの：参加者、結果。

複製時に**採点方式だけは明示的に確認させる**（15点制への移行期のため）。

### O-2-2 名簿は貼り付けで取り込む

CSV / Excel からの**貼り付け**に対応する。ファイル選択ダイアログを経由させない。
列の対応づけは自動推定し、間違っていたら直させる。

### O-2-3 抽選はワンクリック、やり直しも自由

乱数シードを記録して再現可能にする。
**やり直しを何度でも許す。** 確定（Lock）するまでは何度引き直してもよい。

### O-2-4 受付の欠場処理をワンタップにする

朝の受付が負担のピーク。欠場の受理を1タップで完了させ、
**繰り上げ／不戦勝の処理をその場で自動適用する**（設定で選択済みの方式に従う）。

## O-3 入力の負担を減らす

### O-3-1 連続入力モードを持つ

1件確定したら、**次の未入力試合へ自動で進む**。一覧へ戻らせない。
スコアシートが5枚まとまって届くのが現場の実態であり、1件ごとに画面を往復させない。

### O-3-2 試合番号の直接入力

紙のスコアシートには試合番号が印字されている。
番号を打てば該当試合が開く経路を必ず持つ（コート一覧を探させない）。

### O-3-3 目標値は「タップ数」ではなく時間

旧版の「3タップ以内」は、3ゲーム分のスコアを入力する以上、物理的に達成不能だった。

| 対象 | 目標 |
|---|---|
| 画面遷移 | コート選択 → スコア入力 → 確定 の**3ステップ以内** |
| 所要時間 | 1試合の入力を**15秒以内**（3ゲーム、テンキー入力） |
| 連続入力 | 10試合連続の転記を**3分以内** |

### O-3-4 確認ダイアログを挟まない

Undo で守る（UX原則3）。確認は入力を倍遅くする。

### O-3-5 片手で操作できる

テンキーは画面下部固定。もう片方の手は紙とペンを持っている。

## O-4 判断の負担を減らす

### O-4-1 ホーム画面は「いま何をすべきか」だけを出す

機能メニューではなく、行動リストにする。

```
空きコート 2面
  → 次に呼ぶ：MD-24  山田/佐藤（○○クラブ） vs 鈴木/高橋（△△高）
  → 次に呼ぶ：WS-11  ...

結果未入力（20分以上経過） 1件
  → MS-08  3番コート

オーダー未提出 1チーム
  → 決勝T 2回戦 ○○クラブ

進捗  MS 62%  WS 40%  MD 75%
```

### O-4-2 揉め事は「根拠の文」で終わらせる

順位決定の根拠を人間が読める文で出す（`docs/05-ranking-engine.md`）。
運営者が計算を説明する必要をなくす。**画面を見せれば終わる状態を作る。**

これは機能ではなく**中断時間の削減策**である。

### O-4-3 止めない

未完了のブロックがあっても、確定した分から決勝を進められる（`docs/04-formats.md` 3節）。
警告は出すが、進行を止めない。

### O-4-4 異常だけを知らせる

1人運用では画面を見続けられない。
**正常な進行は通知しない。** 通知するのは次の3つだけ。

- コートが空いているのに次が呼ばれていない
- 結果が N 分以上入力されていない試合がある
- オーダーが未提出の Tie がコート待ちになっている

## O-5 中断の負担を減らす

**ここが最大の削減余地であり、既存ツールが手をつけていない領域。**

### O-5-1 聞かれる前に貼り出す

「次いつ？」「何番コート？」は、答えを掲示すれば消える。

| 手段 | 内容 | 優先度 |
|---|---|---|
| 印刷して掲示 | 進行表・結果表。電波に依存しない | P0 |
| 会場内の閲覧リンク | QRコードを掲示。電波があるときのみ | P1 |

閲覧ページに出すのは「自分の次の試合はいつ・どこか」の1点に絞る。
大会全体の結果一覧より、**この1点の方が問い合わせを減らす。**

### O-5-2 呼び出しの回数を減らす

「次に呼ぶ試合」リストを、**2試合先まで**表示する。
呼びに行く回数そのものを減らす（1回の移動で2件呼ぶ）。

### O-5-3 作業を人に委譲できる形にする

1人運用でも、運営者以外に渡せる作業がある。渡せる形で出力する。

| 作業 | 委譲先 | 渡し方 |
|---|---|---|
| 結果の掲示 | 手伝いの人 | 印刷物をそのまま貼る |
| 試合の呼び出し | 手伝いの人 | 「次に呼ぶ」リストを印刷 or 別端末で閲覧 |
| 結果の確認 | 選手・保護者 | 閲覧リンク（QR） |

v2 で「閲覧専用の別端末」を追加するとしても、**書き込みは1台のまま**にする。
同期の作り直しが不要な範囲に留める（`docs/adr/0003`）。

### O-5-4 事故から1人で復帰できる

手伝いがいない前提で、復旧手順は1本に絞る。

- 自動バックアップは黙って走る。運営者は意識しない
- 復旧は「JSONを開く」の1操作。手順書を読ませない
- **パスワードで自分を締め出さない**（`docs/08-non-functional-requirements.md` N-6-1）

---

## この文書の使い方

機能追加の判断は次の順で行う。

1. その機能は O-1〜O-5 のどれを減らすか。**どれも減らさないなら入れない**
2. その機能は運営者に新しい設定・新しい判断を要求しないか。要求するなら、既定値で動くか
3. その機能が壊れたとき、大会は止まるか。止まるなら v1 に入れない
