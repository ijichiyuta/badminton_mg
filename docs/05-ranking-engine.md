# 順位決定ルールエンジン

**本システムの中核。** トーナメント表を描く機能は既存の無料ツールで代替可能だが、ここは代替がない。
紙の集計で最も時間がかかり、最も揉める箇所である。

## 設計方針

1. 判定を **「指標」と「母集団スコープ」の2軸**に分解する（`docs/adr/0006`）
2. ルールはハードコードせず設定値として持つ。ただし**運営者に設定させない**。
   要項パターンのプリセット選択で埋める（`docs/13-operator-load.md`）
3. 判定の**根拠を出力する**。順位だけでなく「なぜその順位になったか」を人間が読める文で返す
4. 実装はテストから書く。本ファイル末尾のテストケースを先に通すこと
5. 外部依存を持たない純粋関数とする。入力は成績データとルールセット、出力は順位と根拠のみ

## 2つの軸

### 軸1：指標（`criteria`）

何を比べるか。順序付きリストで持つ。

| ID | 名称 | 計算 | 備考 |
|---|---|---|---|
| `wins` | 勝利数 | 勝った Match または Tie の数 | |
| `points` | 勝点 | 勝・負・棄権それぞれの設定値の合計 | 既定 1 / 0 / -1 |
| `matchRatio` | 取得マッチ率 | 取得マッチ数 ÷ 実施マッチ数 | 団体戦のみ |
| `gameRatio` | 取得ゲーム率 | 取得ゲーム数 ÷ 実施ゲーム数 | |
| `pointRatio` | 取得ポイント率 | 取得ポイント数 ÷ 総ポイント数 | |
| `matchDiff` | 得失マッチ差 | 取得 − 失注 | |
| `gameDiff` | 得失ゲーム差 | 取得 − 失注 | |
| `pointDiff` | 得失ポイント差 | 取得 − 失注 | |

**「率」と「差」は別物。** 要項によってどちらを使うかが異なるため両方を持つ。

`headToHead`（直接対決）は**指標として持たない**。軸2で表現する。→ `docs/adr/0006`

### 軸2：母集団スコープ（`tiebreakScope`）

誰との対戦成績で比べるか。同率が発生したときにのみ効く。

| 値 | 意味 | 対応する要項の文面 |
|---|---|---|
| `AMONG_TIED` | 同率者同士の対戦のみを抽出して再集計する | 「当該者間の成績による」（最も一般的） |
| `ALL_MATCHES` | 全試合の成績のまま次の指標へ進む | 「ゲーム率の高い者を上位とする」だけが書かれている場合 |
| `AMONG_TIED_IF_TWO` | 2者なら当該者間、3者以上なら全試合 | 「2者の場合は直接対決による。3者以上の場合は…」 |

**2者同率における「直接対決」は、`AMONG_TIED` で `wins` を評価した結果そのものである。**
特別な分岐を書かない。

## アルゴリズム

```
rank(entries, results, rule):
    # 第1段階：全試合の成績を criteria[0] で評価する
    stats  = 全試合から entries の成績を集計
    groups = stats を rule.criteria[0] で評価し、同値ごとにまとめる（降順）

    出力 = []
    現在順位 = 1
    for g in groups:
        if g.size == 1:
            出力に確定として追加（根拠 = criteria[0] の値）
        else:
            出力 += resolve(g, results, rule, 現在順位)
        現在順位 += g.size
    return 出力


resolve(tied, results, rule, 開始順位):
    # 第2段階：母集団を切り替えて criteria[0] から再評価する
    scope = 実効スコープ(rule.tiebreakScope, tied.size)

    if scope == ALL_MATCHES:
        subset = 全試合
    else:
        subset = tied 同士の対戦のみ

    for i in 0 .. rule.criteria.length - 1:        # ★ index 0 から。1 からではない
        指標 = rule.criteria[i]
        if 指標が subset で計算不能（分母が0）:
            continue                                # 0除算しない。次の指標へ
        split = subset の成績を 指標 で評価し、同値ごとにまとめる

        if split.length >= 2:
            # 分割できた。各サブグループを再帰的に解く
            出力 = []
            現在順位 = 開始順位
            for sg in split:
                if sg.size == 1:
                    出力に確定として追加（根拠 = スコープ + 指標 + 値）
                else:
                    出力 += resolve(sg, results, rule, 現在順位)   # 集合は必ず小さくなる
                現在順位 += sg.size
            return 出力

    # すべての指標で分割できなかった
    return 未決着処理(tied, rule.unresolvedAction, 開始順位)
```

### 停止が保証される理由

`resolve` を再帰呼び出しするのは `split.length >= 2` のときだけであり、
そのとき各サブグループは元の集合より**真に小さい**。集合サイズは単調減少するため必ず停止する。

旧版が必要としていた「無限ループ対策」は、この構造では不要になる。
ただし保険として再帰深さの上限（`entries.length`）を置き、超えたら未決着処理へ落とす。

### `AMONG_TIED` で成立しない条件

以下の場合、`AMONG_TIED` は意味をなさない。実装で明示的に扱う。

| 状況 | 対応 |
|---|---|
| 当該者間の対戦がまだ行われていない（リーグ途中） | 順位を**暫定**として出す。確定計算は全試合完了後のみ |
| 棄権者の成績削除設定により当該者間の対戦が消えた | その指標をスキップして次へ。0除算しない |
| 当該者間の対戦が構造上存在しない（別ブロック同士） | `AMONG_TIED` を使わず `ALL_MATCHES` にフォールバックし、根拠にその旨を書く |

**リーグ途中の暫定順位に「確定」と表示してはならない。** 現場で最も信用を失う。

## 未決着処理（`unresolvedAction`）

すべての指標で分割できなかった場合の動作。

| 値 | 動作 |
|---|---|
| `DRAW`（既定） | 抽選。乱数シードを記録し、再現可能にする |
| `SHARED_RANK` | 同順位とする。次の順位は人数分繰り下げる（1位・1位・3位） |
| `PLAYOFF` | 順位決定戦の Stage を生成する（`PLAYOFF` ステージ） |
| `HEAD_TO_HEAD` | **最後の砦としてだけ**当該者間の勝敗を見る。それでも決まらなければ同順位 |

`HEAD_TO_HEAD` は、要項によくある
「上記1〜4で**決まらない場合は**当事者同士で勝った方」という文面のためにある。
これは `tiebreakScope: 'AMONG_TIED'` とは別物である。

- `AMONG_TIED` … **すべての指標**を当該者間で評価する
- `HEAD_TO_HEAD` … 指標は全試合で評価し、**全部使い切ってから**初めて当該者間を見る

同じ「当該者間」でも適用のタイミングが違うので、片方では他方を表現できない。
愛知県社会人クラブリーグ 内規14 が実例（`criteria` は全試合、最後だけ当事者同士）。

**`HEAD_TO_HEAD` でも決まらなければ同順位にする。抽選には落とさない。**
要項がそれ以上を定めていない場面で勝手に抽選すると、運営者が参加者に説明できなくなる。

抽選を実行した場合、**いつ・誰に対して・どのシードで行ったかを操作ログに残す**。
「本当に抽選したのか」を後から示せることが、運営者を守る。

## 特殊な結果の扱い（設定項目）

| 設定 | 実装名 | 選択肢 | 既定 |
|---|---|---|---|
| 試合前の欠場 | `WITHDRAWN` | 基準点-0 として記録／0-0 として記録／記録から除外 | 基準点-0 |
| 試合中の棄権 | `RETIRED` | それまでのポイントを記録／相手の勝利のみ記録 | ポイントを記録 |
| 失格 | `DISQUALIFIED` | 棄権と同じ／別扱い | 棄権と同じ |
| 没収試合 | `WALKOVER` | 棄権と同じ／別扱い | 棄権と同じ |
| 棄権者の他試合 | `removeWithdrawnMatches` | すべて残す／すべて削除する | 残す |
| 棄権者との対戦成績 | `removeFromOpponents` | 相手の成績に残す／**相手の成績からも削除する** | 残す |
| 不戦勝（BYE） | `byeHandling` | 分母から除外（固定） | 除外 |
| 打ち切られた試合 | `NOT_PLAYED` | 分母から除外（固定） | 除外 |

**「基準点-0」は `21-0` ではない。** `ScoringRuleSet.pointsPerGame` を参照する。
15点制なら `15-0`、21点制なら `21-0`。ここに 21 を直書きした時点で設計違反（`docs/adr/0005`）。

### 揉める論点への対応

**「棄権者との対戦成績を全員から削除するか」は、リーグ途中で棄権者が出たときに最も揉める。**
削除すると、棄権者に勝っていた選手の成績が減り、順位が入れ替わることがある。
要項に規定がない大会が多い。

対応：**両方の結果を並べて提示する UI を用意する。**
運営者が選ぶのではなく、「どちらを選んでも順位が同じ」ならその事実を出し、
異なる場合のみ選択を求める。同じであれば運営者の判断は不要になる（負担削減）。

## 根拠の出力

`rank()` は順位配列だけでなく、判定過程を返す。

```
[
  { rank: 1, entryId: "A", reason: "3勝0敗" },
  { rank: 2, entryId: "C", reason: "1勝2敗。B・Dと並んだため当該3者間で再集計し、取得ゲーム率 0.667 で上回った" },
  { rank: 3, entryId: "B", reason: "1勝2敗。当該3者間の取得ゲーム率 0.500" },
  { rank: 4, entryId: "D", reason: "1勝2敗。当該3者間の取得ゲーム率 0.333" }
]
```

根拠の文は次の要素で構成する。

1. 全試合の成績（`3勝0敗`）
2. 同率が発生した事実と相手（`B・Dと並んだため`）
3. 適用したスコープ（`当該3者間で再集計し`）
4. 決め手となった指標と値（`取得ゲーム率 0.667 で上回った`）
5. 該当する場合のみ：抽選・同順位・混在採点方式の注記

この文字列をそのまま画面に表示し、印刷物にも載せる。
**機能としてではなく、運営者が選手に説明するための信用装置として実装する。**

## 団体戦の集計階層

団体戦では集計が2階層になる。`matchRatio` と `gameRatio` は参照する階層が違う。

```
Tie（チーム対チーム）    ← wins / points はここを数える
 └─ Match（個人の1試合） ← matchRatio はここを数える
     └─ Game            ← gameRatio はここを数える
         └─ Point       ← pointRatio はここを数える
```

`NOT_PLAYED`（打ち切り）の Match は、`matchRatio` `gameRatio` `pointRatio` の
**分母と分子の両方から除外する**。

### 実装上の対応（2026-09-14 に実装）

`EntryStats` は勝敗を2組持つ。

| フィールド | 単位 |
|---|---|
| `wins` / `losses` | **Tie**（団体戦）。個人戦では Match と一致する |
| `matchesWon` / `matchesLost` | **Match**。`matchRatio` `matchDiff` はこちらを見る |

Tie の帰属は `Match.tieId` で決まる。`tieId` が `null` の試合は、その試合自体を1つの Tie とみなす。
これで個人戦と団体戦が同じコードで通り、個人戦では `wins === matchesWon` になる。

Tie の勝者は**その Tie で勝ちマッチ数が多い側**。同数なら引き分けとして、
どちらの勝敗にも数えない（要項に定めがないため勝手に決めない）。
勝点（`points`）と棄権減点（`pointsForRetirement`）も Tie 単位で付く。

**この階層を潰すと要項の第2基準が死ぬ。**
「1. 勝敗による 2. マッチ得失率による」が2段構えで書かれているのは、
2複1単なら1対戦=3マッチで、両者が別の数だから。

## RankingRuleSet

**既定値は第1号提供先の要項に合わせる**（`docs/17-first-customer.md`）。

> リーグ戦にて**勝敗数が同じ場合はゲーム勝率**にて、ゲーム勝率が同じ場合は**得失点差**にて順位を決定します。

```jsonc
{
  "criteria": ["wins", "gameRatio", "pointDiff"],
  "tiebreakScope": "ALL_MATCHES",
  "unresolvedAction": "DRAW",
  "pointsForWin": 1,
  "pointsForLoss": 0,
  "pointsForRetirement": -1,
  "withdrawnHandling": "BASE_POINT_TO_ZERO",
  "retiredHandling": "KEEP_POINTS",
  "disqualifiedHandling": "SAME_AS_RETIRED",
  "walkoverHandling": "SAME_AS_RETIRED",
  "removeWithdrawnMatches": false,
  "removeFromOpponents": false,
  "drawSeed": null,
  "presetId": "standard-among-tied"
}
```

`criteria` の末尾に `draw` を置かない。未決着は `unresolvedAction` で扱う。

### 既定値が「率」ではなく「差」である理由

第3基準は `pointRatio`（取得ポイント率）ではなく **`pointDiff`（得失点差）**。
要項の原文が「得失点差」だからである。**要項の言葉をそのまま実装名に対応させる。**

### 既定が `ALL_MATCHES` である理由と、そこにある穴

要項には「当該者間の成績による」に相当する記載が**ない**。
素直に読めば全試合のゲーム勝率であり、`ALL_MATCHES` になる。

しかし要項には次も書かれていない。

| 書かれていないこと | なぜ問題か |
|---|---|
| **3者以上が同率の場合の規定** | 4チームリーグで**各ブロック1位・2位を表彰**する。2位を必ず決める必要がある |
| 得失点差まで同じ場合の規定 | 抽選か、順位決定戦か、同順位かが決まらない |
| 棄権者が出た場合の扱い | 成績を残すか削除するかで順位が変わる |

**この3つは要項を何度読んでも埋まらない。現場の慣習でしか決まらない。**
→ `docs/00-open-questions.md` E-4 / E-5 / E-8 / **E-9（過去に揉めた実例）**

実装では `tiebreakScope` を設定で切り替えられるようにし、
**`ALL_MATCHES` と `AMONG_TIED` で順位が変わるデータを検知したら、両方を並べて提示する。**
運営者が要項の解釈を決める材料になる（O-1-2）。
