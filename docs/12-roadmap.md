# ロードマップ

## v1：対象大会を1回完走する

**対象は新日本スポーツ連盟 愛知バドミントン協議会**（`docs/17-first-customer.md`）。

**成功の定義：対象の大会を1回、システムだけで完走できること。**
初回は紙と並行運用するため、「紙より速く、紙と同じ結果が出た」で成功とみなす。

### 対象大会の実態からスコープを絞る

第1号提供先の個人戦は **リーグ戦のみ**（各ブロック1位・2位を表彰）。
決勝トーナメントは実質行われない。したがって **v1 は `ROUND_ROBIN` を完璧にすることを優先する。**

| 形式 | v1 での位置づけ |
|---|---|
| `ROUND_ROBIN`（4〜5チーム、複数ブロック） | **最優先。これだけで愛知の個人戦は完走できる** |
| `SINGLE_ELIMINATION` | 全国団体戦の決勝（8チーム→各1位）で必要。小規模で足りる |
| 団体戦（3複・種別制約・Stage単位の打ち切り） | 全国大会用。個人戦の完走後 |
| `CONSOLATION` / `PLAYOFF` | v1 では作らない |

**128ドローのトーナメントは v1 に不要。** 対象大会に存在しない。
`SINGLE_ELIMINATION` は 2〜16 で足りる。

含むもの：

- 大会・種目・参加者の登録
- 4形式すべての組み合わせ作成（自動＋手動調整）
- 結果入力と自動集計
- 順位決定ルールエンジン
- トーナメント表／リーグ表の表示と印刷
- JSON エクスポート・インポート
- 完全なオフライン動作
- 速報の日和見アップロード（P1。間に合わなければ落とす）

### 実装順序

順位決定エンジンから作る。UI から作らない。

| # | 対象 | 完了条件 |
|---|---|---|
| 1 | ドメイン層：採点判定（`ScoringRuleSet` 駆動） | 15点制・21点制の両方で境界値テストが通る |
| 2 | ドメイン層：順位決定エンジン | `docs/05` の T-01〜T-20 が全て通る |
| 3 | ドメイン層：組み合わせ生成（ブラケット・シード・BYE） | 4〜128 で `S(N)` が自己逆写像になることを検証 |
| 4 | ドメイン層：進出処理（交差配置・部分進出） | 3/4/5ブロックのパターンが通る |
| 5 | 永続化層 | タブを閉じて再読込しても完全復元 |
| 6 | UI：結果入力画面（最重要） | 1試合15秒、10試合3分を実測 |
| 7 | UI：ホーム画面（行動リスト） | 判断を求めるモーダルが1大会5回以内 |
| 8 | UI：トーナメント表・リーグ表 | 200名で描画1秒以内 |
| 9 | 印刷 | A4で実際に印刷して読めることを確認 |
| 10 | 同期 | オフラインのまま全機能が動くことを先に確認してから着手 |

**1〜4 は UI なしで完結する。** ここまでをテストだけで積み上げてから画面に入る。

### 15点制への移行に関する注意

既定は15点制だが、**対象大会の次回開催が15点制か21点制かは要確認**（Q F-1）。
どちらであっても、採点方式がプリセット1タップで切り替わり、
順位決定の「基準点-0」記録が正しく追従することを、リハーサルで必ず確認する。

## v3 以降

大会をまたいだ選手戦績の蓄積。
ここに進むには **同一人物の名寄せ**という難問を解く必要がある。
氏名と所属だけでは同姓同名と移籍を区別できない。v1・v2 では手を出さない。

エントリー受付・決済は、複数の大会で継続利用される実績ができてから検討する。
