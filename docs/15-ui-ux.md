# UI / UX 仕様

`docs/09-ux-principles.md` が原則、`docs/13-operator-load.md` が負担の分析、**本書がその具体化**。
画面とインタラクションの実装判断は本書に従う。

## 設計の前提

| 項目 | 実態 |
|---|---|
| 使う人 | 運営者1人。年配であることが多い |
| 場所 | 体育館。照明は明るいが色温度が高く、反射が強い |
| 姿勢 | 立っている。**片手はスコアシートとペンで塞がっている** |
| 端末 | 協会の共用 PC、私物のタブレット、スマホ。一定しない |
| 中断 | 常に話しかけられる。作業は必ず途中で止まる |
| 頻度 | **年1回。前回の操作は覚えていない** |

最後の行が重要。**毎回が初回である**前提で設計する。
覚えていることに依存した導線（隠しジェスチャ、長押し、二段メニュー）は成立しない。

# 第1部：設定を減らす4つの仕掛け

「全部の形式に対応する」と「毎回の入力が面倒でない」を両立させる方法。
**柔軟性はデータモデルに持たせ、UI には出さない。**

## 仕掛け1：段階的開示

設定は3層に分ける。**第1層だけで大会が完走できること**が要件。

| 層 | 何を出すか | 何回触るか |
|---|---|---|
| **第1層：既定** | 何も出さない。既定値のまま進める | 0回 |
| **第2層：プリセット** | よくある選択肢をカードで4〜6個 | 1回 |
| **第3層：詳細設定** | 全項目を個別指定。折りたたみの中 | ほぼ0回 |

第2層に出すのは**その大会で実際に起きる選択肢だけ**。
11点以下・時間制・上限なしは「その他の形式」を開いたときだけ出す（Q F-6 が「たまにある」のため）。

```
採点方式
┌────────────────┐ ┌────────────────┐
│ 15点 3ゲーム     │ │ 21点 3ゲーム     │
│ ●選択中          │ │                │
└────────────────┘ └────────────────┘
┌────────────────┐ ┌────────────────┐
│ 15点 1ゲーム     │ │ 21点 1ゲーム     │
└────────────────┘ └────────────────┘

  ▸ その他の形式（11点・時間制・上限なし）
  ▸ 詳細設定
```

## 仕掛け2：マトリクス一括編集

種目・ステージごとに方式が違う大会がある（Q F-8 / F-9 がともに「両方ある」）。
**1つずつ開かせない。全体を1画面で見せて、そこで直す。**

```
採点方式                         [ 一括変更 ▾ ]

                  予選リーグ      決勝トーナメント
─────────────────────────────────────────────
男子S A級          15点3G         15点3G          ← 薄字＝継承
男子S B級          15点1G ●       15点3G          ← 濃字＝上書き
女子S              15点3G         15点3G
男子D              15点3G         15点3G
女子D              15点3G         15点3G
団体               21点3G ●       21点3G ●
─────────────────────────────────────────────
                   ↑列ヘッダをタップで列ごと一括変更
 ↑行ヘッダをタップで行ごと一括変更
```

- **継承しているセルは薄字、上書きしたセルは濃字＋`●`。** 何を触ったかが一目で分かる
- 行ヘッダ・列ヘッダのタップで一括変更
- セルのタップで個別変更
- 上書きを消す操作（「継承に戻す」）を必ず用意する

順位決定ルールも同じマトリクスで扱う（列はステージではなく種目のみ）。

## 仕掛け3：前年からの複製 + 差分だけ確認

**2年目以降は設定をゼロにする。** ホーム画面で「新しい大会」より上に置く。

```
┌──────────────────────────────────┐
│  前年の大会から作る                  │
│  第42回○○市民大会（2025-11-03）     │
│                        [ 選ぶ ] │
└──────────────────────────────────┘
    新しい大会をゼロから作る
```

複製後、**変わった可能性がある項目だけ**を1画面で確認させる。

```
複製しました。次の3点だけ確認してください。

  開催日      2025-11-03  →  [ 2026-11-02 ]
  採点方式    21点3ゲーム  →  [ 変更する ]   ← 15点制への移行期のため必ず確認
  コート数    6面         →  [ 6面 ]

  種目6件・順位決定ルール・印刷設定は前年のまま引き継ぎました。
                                        [ このまま進む ]
```

採点方式だけ強調するのは、移行期に「21点のつもりで15点」「15点のつもりで21点」の
取り違えが必ず起きるため。

## 仕掛け4：要項テキストの貼り付け

**最も効く仕掛け。** 大会要項の該当箇所を貼り付けると、設定を推定して確認だけ求める。

```
大会要項の「試合方法」「順位決定」の部分を貼り付けてください（任意）

┌────────────────────────────────────────────┐
│ 3ゲーム15点法とする。ただし予選リーグは       │
│ 1ゲーム15点法とする。                        │
│ 順位は勝数により決定する。勝数が同数の場合は  │
│ 当該者間の成績により、なお同じ場合はゲーム率、 │
│ ポイント率の順により決定する。                │
└────────────────────────────────────────────┘
                                  [ 読み取る ]

読み取りました。これで合っていますか。

  採点方式      予選 15点1ゲーム → 決勝 15点3ゲーム
  順位決定      勝数 → 当該者間の成績 → ゲーム率 → ポイント率
  同率の扱い    当該者間で再計算する

                       [ 違う ]      [ これで進む ]
```

推定はキーワード照合で足りる。LLM は使わない（オフラインで動く必要があるため）。

| 拾うキーワード | 設定 |
|---|---|
| `15点` `15ポイント` `21点` `11点` | `pointsPerGame` |
| `3ゲーム` `1ゲーム` `一本` | `gamesPerMatch` |
| `最大○ポイント` `上限○点` | `maxPoints`（**17 / 21 / 30 が実在**） |
| `○オール延長` `○オールデュース` | `deuceFrom` |
| `2点差` `二点差` | `twoPointLead = true` |
| `打ち切り` `打切り` `延長なし` | **`twoPointLead = false`**（団体戦の打ち切りとは別） |
| `インターバル○点` | `intervalAt` |
| `予選` + 別の点数表記 | ステージ上書き |
| `分` + `勝敗` | `winCondition = TIME` |
| `当該者間` `当事者間` | `tiebreakScope = AMONG_TIED` |
| `直接対決` + `2者` | `AMONG_TIED_IF_TWO` |
| `ゲーム率` `ゲーム得失` | `gameRatio` / `gameDiff` |
| `ポイント率` `点数率` `得失点` | `pointRatio` / `pointDiff` |
| `勝点` | `points` |
| `勝敗数` `勝数` | `wins` |
| `ゲーム勝率` `ゲーム率` | `gameRatio` |
| `得失点差` `得失点` | **`pointDiff`**（率ではない） |
| `抽選` | `unresolvedAction = DRAW` |
| `全試合実施` `すべて実施` | `truncate = false` |
| `○勝先取` | `truncate = true` |
| `敗者審` | 審判割当 = 敗者審 |

**推定できなかった項目は既定値のまま残し、「読み取れませんでした」と明示する。**
勝手に埋めない。

# 第2部：画面仕様

## 画面一覧

```
[大会一覧]
   ├─ [大会作成ウィザード]  3問 + 任意の要項貼り付け
   └─ [大会]
        ├─ ★[ホーム]        当日の運営画面。既定の着地点
        ├─ [参加者]
        ├─ [組み合わせ]
        ├─ ★[結果入力]      最重要
        ├─ [表示]           トーナメント表 / リーグ表 / 順位
        ├─ [印刷]
        └─ [設定]           採点方式マトリクス / 順位決定 / コート / 公開
```

**階層は2段まで。** 大会 → 画面。それ以上潜らせない。
下部タブで `ホーム / 入力 / 表示 / 印刷 / 設定` を常時出す。

  級を分ける場合はここで足します

                         [ 戻る ] [ 次へ ]

── 3/3 ──────────────────────────────
進め方は？

  ┌──────────────────┐ ┌──────────────────┐

  ┌─────────────────────────────────┐

  └─────────────────────────────────┘
  ┌─────────────────────────────────┐
  │ 8ブロック2組 → 決勝トーナメント      │

抽選後：

```
A組                  B組                C組

## 5. ★結果入力画面（最重要）

### 入力方式

紙のスコアシートには両者の点数が書かれている。**その通りに6個の数字を順に打つ。**
タブ移動もタップも挟まない。

```
┌────────────────────────────────────────┐
│ ← MD-24            3番コート    15点3G   │
├────────────────────────────────────────┤
│                                        │
│   山田/佐藤            鈴木/高橋         │
│   ○○クラブ            △△高校           │
│                                        │
│      ┌────┐          ┌────┐          │
│  1G  │ 15 │    －    │  9 │          │
│      └────┘          └────┘          │
│      ┌────┐          ┌────┐          │
│  2G  │ 13 │    －    │[15]│  ← 入力中  │
│      └────┘          └────┘          │
│      ┌────┐          ┌────┐          │
│  3G  │    │    －    │    │          │
│      └────┘          └────┘          │
│                                        │
│   ▸ 棄権・失格・不戦勝                   │
│                                        │
├────────────────────────────────────────┤
│    1      2      3                     │
│    4      5      6         ⌫           │
│    7      8      9                     │
│    0            確定                    │
└────────────────────────────────────────┘
```

### 入力の挙動（ここが速度を決める）

| 挙動 | 内容 |
|---|---|
| **自動フォーカス移動** | 数字を確定すると次のマスへ自動で移る。タブ・タップ不要 |
| **勝ち点の自動補完** | 基準点未満の数字（9 など）を打つと、**相手側に基準点を自動で入れる**。1ゲーム1タップで済む |
| **デュース検知** | 基準点-1 以上（15点制なら14以上）を打つと補完せず、両方の入力を求める |
| **決着で自動終了** | `gamesToWin` を満たした時点で残りのゲーム欄を畳む |
| **勝者の自動判定** | 判定できないときだけ勝者選択を出す |
| **1ゲーム制** | ゲーム欄を1行だけ出す |
| **時間制** | 補完・上限検証を行わない。両方の数字を入力する |

**「9」と打つだけで `15 - 9` が入る。** これが最大の短縮になる。
勝った側が基準点ちょうどで終わる試合が大半だからである。

自動補完した数字は**薄く表示**し、タップで上書きできる。何が自動かを隠さない。

### 確定後

```
確定 → 次の未入力試合へ自動で進む
     ↓
┌────────────────────────────────────────┐
│ MD-24 を記録しました        [ 取り消す ] │  ← 5秒で消えるトースト
└────────────────────────────────────────┘
```

**確認ダイアログを出さない。** トーストの `[取り消す]` で守る（原則3）。
連続入力モードでは一覧に戻らず、次の未入力試合がそのまま開く。

### 試合番号からの直接入力

紙のスコアシートには試合番号が印字されている。
入力画面の上部に**常時**番号入力欄を置く。コート一覧を探させない。

```
  試合番号  [ MD-24 ]  → 開く
```

### 警告の出し方

```
┌────────────────────────────────────────┐
│ ⚠ 15 - 16 は決着していません              │
│    この種目は 15点制（上限21）の設定です   │
│                                        │
│         [ 直す ]      [ このまま確定 ]   │
└────────────────────────────────────────┘
```

- **必ず設定値を添える**（「不正な値です」とだけ出さない）。移行期は設定の取り違えが原因であることが多い
- `[このまま確定]` を必ず残す（原則5）。ボタンの並びは「直す」が左、「確定」が右

## 6. リーグ表（星取表）

**現行の紙の書式に合わせる。** 見比べて「同じもの」と言えることが導入の条件になる
（`docs/17-first-customer.md`）。

```
男子1部                  15ポイント3ゲーム 14オール延長2点差 最大17    暫定

   所属        氏名        1    2    3    4    勝敗   順位
──────────────────────────────────────────────────
 1 ○○○○     ＡＡ ＡＡ          ①    ③    ⑤    2-1    1位
            ＢＢ ＢＢ          9    35   61          暫定
            　            15-9  15-11 13-15
──────────────────────────────────────────────────
 2 △△△△     ＣＣ ＣＣ    ①          ⑥    ④    1-2    3位
            ＤＤ ＤＤ    9          62   36          暫定
                       9-15        ―    ―
──────────────────────────────────────────────────
```

### 現行から引き継ぐ点

| 要素 | 仕様 |
|---|---|
| 1エントリー = 2行 | 所属＋氏名2名を縦に並べる（ダブルスが基本のため） |
| **マス内に2種類の番号** | **丸数字＝ブロック内の試合順（①〜⑩）／算用数字＝大会全体の通し試合番号** |
| ヘッダ右に採点方式 | **ブロックごとに違うため必須**。省略しない |
| 勝敗列・順位列 | 右端に固定 |

### 追加する点

| 要素 | 仕様 |
|---|---|
| スコア | マス内に3行目としてスコアを出す（紙にはない。画面と印刷で追加） |
| **空きマスをタップで入力** | その試合の入力画面が直接開く |
| 暫定バッジ | 全試合が終わるまで順位に `暫定` を出し続ける |
| 未実施 | `―` で表す（打ち切り・不戦勝と区別する） |

**紙にない情報を足すのはよいが、紙にある情報を落とさない。**
特に通し試合番号は、スコアシートとタイムテーブルを紐づける唯一の鍵である。

## 7. 順位の確定と根拠

```
A組  順位が確定しました

  1位  山田/佐藤 (○○クラブ)
       3勝0敗

  2位  田中/伊藤 (△△高校)
       ┌──────────────────────────────────┐
       │ 1勝2敗。鈴木組・佐藤組と並んだため   │
       │ 当該3者間で再集計し、               │
       │ 取得ゲーム率 0.667 で上回りました。  │

# 第3部：インタラクション規約

## タップとサイズ

| 対象 | 規定 |
|---|---|
| タップ領域 | 最小 44 × 44 px |
| 主要操作の位置 | **画面下部**。片手の親指が届く範囲 |
| テンキー | 画面下部に固定。1キーの高さ 56px 以上 |
| 隣接ボタンの間隔 | 8px 以上 |
| 長押し | **使わない**（年1回の利用では覚えていない） |
| スワイプ | 削除などの破壊的操作に割り当てない |
| ダブルタップ | 使わない |

## 取り消し（Undo）

| 規定 | 内容 |
|---|---|
| 確認ダイアログ | **原則として出さない** |
| トースト | 画面下部。5秒表示。`[取り消す]` を含む |
| 取り消せる範囲 | 結果入力、抽選、欠場処理、進出の流し込み、順位の手動上書き |
| 例外的に確認を出す | 大会の削除、組み合わせの確定解除（＝試合番号の振り直し） |

トーストはテンキーを覆わない位置に出す。**連続入力を止めない。**

## モーダル

原則として使わない（原則4）。例外は次の2つだけ。

1. 設定で結果が変わるときの二者択一（順位が入れ替わる場合など）
2. 破壊的操作の確認（上の「例外的に確認を出す」の2つ）

モーダルを出す場合、**閉じても入力内容が失われないこと。**

## スクロール

| 規定 | 内容 |
|---|---|
| ページ全体の横スクロール | **禁止** |
| 広い表（トーナメント表・マトリクス） | その要素の中だけ横スクロール。`overflow-x: auto` |
| ホーム画面 | 375px 幅で縦スクロールなしに収める |
| 結果入力画面 | 縦スクロールなし。テンキーは固定 |

## キーボード（PC 利用時）

PC の共用機で使われる可能性が高い。テンキーでの入力を成立させる。

| キー | 動作 |
|---|---|
| `0`〜`9` | スコア入力 |
| `Enter` | 確定 → 次の試合へ |
| `Backspace` | 1文字削除 |
| `Tab` / `→` | 次のマス |
| `Esc` | 入力を破棄して戻る |
| `Ctrl/Cmd + Z` | 取り消し |

# 第4部：視覚設計

## 配色

体育館の照明（高色温度・強い反射）で判読できることを優先する。
**v1 ではダークモードを出さない。** 印刷物と見た目を揃えるため。

| 用途 | 色 | コントラスト比 |
|---|---|---|
| 背景 | 白 `#FFFFFF` | — |
| 本文 | ほぼ黒 `#1A1A1A` | 16:1 |
| 副次テキスト | `#5A5A5A` | 7:1 |
| 継承値・自動補完値 | `#9A9A9A` | 4.5:1（下限） |
| 主要操作 | 濃い青 `#1D4ED8` | 8:1 |
| 警告 | 濃い橙 `#B45309` + アイコン | 5:1 |
| 完了・勝ち | 濃い緑 `#15803D` | 5.5:1 |

**色だけで意味を伝えない。** 必ずアイコンか文字を添える（体育館の照明では色の判別が落ちる）。

## 文字サイズ

3段階を**設定画面ではなく、常時アクセスできる位置**に置く。

```
  A−   A   A＋      ← ヘッダ右端に常時表示
```

| 段階 | 本文 | 数字（スコア） |
|---|---|---|
| 小 | 14px | 20px |
| 標準 | 16px | 24px |
| 大 | 20px | 32px |

スコアの数字は本文より必ず大きくする。遠目で読む場面が多い。

## 状態の表現

**色に加えて、形と文字で区別する。**

| 状態 | 表現 |
|---|---|
| 未入力 | 点線の枠 + 薄いグレー |
| 進行中 | 実線の青枠 + `進行中` |
| 完了 | 通常表示 + スコア |
| 暫定 | `暫定` バッジ（黄地・黒文字） |
| 確定 | `確定` バッジ（緑地・白文字） |
| 警告あり | `⚠` + 橙の左罫線 |
| 不戦勝 | `BYE`（グレー地） |
| 実施せず | `実施せず`（打ち切り。グレー地・取り消し線なし） |
| 未同期 | ヘッダ右に `未同期 12件`（文字のみ。点滅させない） |

# 第5部：空・エラー・読み込み

| 状況 | 表示 |
|---|---|
| 参加者0名 | 「Excel から貼り付けて始めましょう」＋貼り付け欄を直接出す |
| 組み合わせ未作成 | 参加者数と、おすすめの形式カードを出す |
| 未入力の試合なし | 「すべて入力済みです」＋次のステージへの導線 |
| 想定外のエラー | **直前の状態を保ったまま**、該当部分だけ「表示できません」に差し替える。画面全体を落とさない |
| 読み込み中 | スピナーを出さない。前の内容を残したまま更新する（オフラインなので通常は即時） |
| 同期失敗 | ヘッダの表示が `未同期 N件` に変わるだけ。**ダイアログを出さない** |
| ストレージ逼迫 | 起動時に1回だけ「バックアップを取ってください」＋エクスポートボタン |

# 第6部：実装時の検証項目

UI ができた時点で、次を実測する。満たさないなら機能を削る。

| # | 検証 | 基準 |
|---|---|---|
| V-1 | 1試合（3ゲーム）の入力時間 | **15秒以内** |
| V-2 | 10試合の連続転記 | **3分以内** |
| V-3 | 大会作成から組み合わせ確定まで（前年複製あり） | **5分以内** |
| V-4 | 同（新規・要項貼り付けあり） | **15分以内** |
| V-5 | ホーム画面が 375px 幅で縦スクロールなしに収まる | 収まる |
| V-6 | 運営者に判断を求めるモーダルの表示回数 | **1大会5回以内** |
| V-7 | ページ全体の横スクロールが発生しない | 発生しない |
| V-8 | すべてのタップ領域が 44px 以上 | 全て |
| V-9 | 文字サイズ「大」でレイアウトが崩れない | 崩れない |
| V-10 | ネットワークを切った状態で V-1〜V-9 が成立する | 成立する |

**V-1 と V-6 が、この製品が使われるかどうかを決める。**
