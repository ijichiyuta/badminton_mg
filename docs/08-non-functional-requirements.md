# 非機能要件

## 最優先：データを失わない

年に1回の大会で、失敗すると翌年はない。**可用性とデータ保全が機能数より優先する。**

| ID | 要件 |
|---|---|
| N-1-1 | すべての操作を即時に永続化する。明示的な保存ボタンに依存しない |
| N-1-2 | ブラウザのタブを閉じても、再読み込みしても、状態が完全に復元される |
| N-1-3 | 端末が1台壊れた場合の復旧経路を必ず用意する（JSON エクスポート） |
| N-1-4 | ストレージ消去の警告。大会開始時にバックアップを促す |
| N-1-5 | 自動バックアップは世代管理する。直近の N 世代を保持 |

## 可用性

| ID | 要件 |
|---|---|
| N-2-1 | 大会当日の稼働時間（8時〜18時程度）を通じて動作し続ける |
| N-2-2 | **ネットワークが存在しない状態で、全機能が動作する**（アップロードを除く） |
| N-2-3 | 同期の失敗が運営画面の操作を1秒も止めない |
| N-2-4 | サーバが落ちていても大会運営に影響しない |
| N-2-5 | エラーが発生しても、直前の状態を失わずに継続できる |

## パフォーマンス

| ID | 要件 |
|---|---|
| N-3-1 | 結果入力から画面反映まで 100ms 以内 |
| N-3-2 | 200名規模の大会でトーナメント表の描画が 1 秒以内 |
| N-3-3 | 順位再計算が 200ms 以内 |
| N-3-4 | 初回読み込み後はオフラインで即時起動する |

## 対応環境

| ID | 要件 |
|---|---|
| N-4-1 | ブラウザ：Chrome / Edge / Safari の現行版および1つ前 |
| N-4-2 | 画面：スマートフォン縦持ちから PC まで。最小 375px 幅で操作可能 |
| N-4-3 | インストール不要。URL を開くだけで使える |
| N-4-4 | 管理者権限を必要としない |

体育館に持ち込まれる PC は協会の共用機であることが多く、インストール権限がない場合がある。
また、電波がない会場ではアプリストアからのダウンロードができない。→ `docs/adr/0004`

## 表示・アクセシビリティ

| ID | 要件 |
|---|---|
| N-5-1 | 文字サイズを3段階以上で切り替えられる |
| N-5-2 | 体育館の照明条件でも判読できるコントラスト |
| N-5-3 | 片手で操作できる。主要操作を画面下部に配置する |
| N-5-4 | タップ領域は最小 44px 四方 |

運営担当者は年配であることが多く、もう片方の手は紙とペンを持っている。

## セキュリティ・プライバシー

| ID | 要件 |
|---|---|
| N-6-1 | **端末内の大会データにパスワードをかけない。** 端末のロックは OS に委ねる |
| N-6-2 | パスワードが必要なのは**公開ページの更新用トークンのみ**。発行は任意 |
| N-6-3 | 更新用トークンを紛失しても、大会運営は一切影響を受けない |
| N-6-4 | 公開ページに出す個人情報の範囲を設定できる（フルネーム／姓のみ／所属のみ） |
| N-6-5 | 未成年の氏名公開について、運営者が明示的に選択する |
| N-6-6 | 参加者名簿に生年月日・連絡先が含まれる場合、それらは公開対象から常に除外する |
| N-6-7 | アカウント登録を要求しない |

### N-6-1 を旧版から変更した理由

旧版は「大会データは管理者パスワードで保護する」としていた。
**1人運用では、これが単一障害点になる。**

パスワードを忘れた瞬間に大会が止まり、復旧できる人が他にいない。
「システムが正しさを主張して大会を止めることは最悪の失敗」という UX 原則5に
真正面から反する。

端末内のデータは端末の物理的な管理と OS のロックで守る。
アプリ側の暗号化・パスワードは持たない。
守る対象は「公開ページを第三者に書き換えられないこと」だけであり、
それには更新用トークンで足りる（`docs/10-architecture.md`）。

## 1人運用の成立条件

`docs/13-operator-load.md` の設計を、検証可能な水準として置く。

| ID | 要件 |
|---|---|
| N-8-1 | 順位決定ルールの設定が、プリセット選択1回で完了する |
| N-8-2 | 採点方式の設定が、プリセット選択1回で完了する |
| N-8-3 | 前年大会の複製から参加者登録までが、名簿の貼り付け1回で完了する |
| N-8-4 | 1試合の結果入力が15秒以内、10試合の連続転記が3分以内 |
| N-8-5 | 運営者が手を止めて判断を求められる場面が、1大会あたり5回以内 |
| N-8-6 | 復旧操作が「JSONを開く」の1操作で完了する |
| N-8-7 | 正常な進行に対する通知を行わない。通知は異常の3種類のみ |

N-8-5 は測定方法を決めておく。**確認・選択を求めるモーダルの表示回数**で数える。

## 保守性
